# Definition of done

Date: 2026-10-22 | Status: proposed standard

## Initial Phase 0 documentation package

- Official repository, branch, remote and initial status verified; existing files preserved.
- All requested local documents exist in English, with linked owners, boundaries and deliverables.
- Twelve feature hypotheses assessed; A/B/C options compared with an unapproved recommendation.
- Public-source claims have URLs/dates and limitations; no fabricated interviews or claims of efficacy.
- Research not performed and approvals not granted are explicitly visible.
- Local paths/links, required coverage, approval consistency and final Git scope checked.
- Chinese Founder report delivered; stop for review. This means initial setup complete, not validated discovery or an approved phase transition.

## Future discovery completion

Approved research actually completed or scope explicitly revised; consent/data handling checked; results and negative cases synthesized; hypotheses updated; evidence gaps and safety/technical feasibility assessed; MVP decision brief prepared. Founder explicitly decides whether discovery is sufficient for Phase 1. A study plan alone does not satisfy this gate.

## Future feature completion

- Approved versioned PRD, acceptance criteria and relevant decisions are linked; no unexplained scope changes.
- Usable vertical slice satisfies every acceptance criterion, including empty, error, loading, cancellation and recovery behavior.
- Contracts, ownership authorization, validation, migrations and rollback are reviewed where applicable.
- Appropriate unit/integration/contract/E2E checks pass; independent review is performed by someone other than the implementer.
- AI schema/fallback and versioned safety/usefulness regression evaluation pass approved thresholds; critical failures block release regardless of aggregate scores.
- Accessibility includes keyboard, focus order, screen-reader comprehension, contrast and reduced-motion checks for relevant flows; proposed target WCAG 2.2 AA requires approval and a testable checklist.
- Privacy review confirms purpose/minimization, provider terms, access, retention/deletion and safe logs. Qualified review covers any psychological content.
- Security checks address task ownership, injection, secrets, dependencies and abuse paths.
- Observability, cost limits, support ownership and rollback are ready for the approved environment.
- Product/QA acceptance evidence is recorded; no unresolved critical/high safety or security defects. Lower-severity exceptions require named owner, expiry and authorized acceptance.
- Founder approves release when required; no deployment occurs merely because implementation is complete.

## Evidence and status

An evidence bundle includes changed behavior, acceptance mapping, actual commands/check results, evaluation versions, reviewer findings, unresolved limitations and approval references. Do not mark unexecuted tests “passed” or an unreviewed document “signed off.” Use draft, ready for review, reviewed, accepted and released accurately.
